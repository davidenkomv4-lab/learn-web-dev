# [Тестирование] Задание 1. Сценарий записи и требования

Продукт: сайт салона **ÉLAIRE**. Сценарий записи состоит из трёх экранов:
**Выбор услуги** → **Дата и время** → **Подтверждение**.

---

## 1. Основной пользовательский сценарий (happy path)

```
Клиент записывается на услугу
│
├── 0. Начало
│   ├── 0.1. Открыть главную страницу салона
│   └── 0.2. Нажать кнопку «Записаться на услугу»
│
├── 1. Выбор услуги (экран 1 из 3)
│   ├── 1.1. Открыть каталог услуг — в индикаторе шагов активен шаг «1. Выбор услуги»
│   ├── 1.2. Выбрать категорию в боковом меню (Стрижки / Маникюр / Брови / Спа)
│   ├── 1.3. Просмотреть список услуг категории: название, описание, длительность, цена
│   └── 1.4. Нажать «Выбрать» у нужной услуги → переход на экран выбора даты
│
├── 2. Выбор даты и времени (экран 2 из 3)
│   ├── 2.1. Увидеть календарь текущего месяца; шаг «Выбор услуги» отмечен ✓
│   ├── 2.2. При необходимости перелистнуть месяц стрелками «‹» / «›»
│   ├── 2.3. Выбрать доступный день (не раньше сегодняшнего)
│   ├── 2.4. Просмотреть свободные слоты времени на выбранный день
│   ├── 2.5. Выбрать свободный слот
│   ├── 2.6. Проверить выбранные дату и время в нижней панели
│   │        (например, «Пятница, 17 октября 2026 • 12:00»)
│   └── 2.7. Нажать «Далее» → переход на экран подтверждения
│
└── 3. Подтверждение (экран 3 из 3)
    ├── 3.1. Проверить детали визита: услуга, дата и время, мастер, длительность, сумма к оплате
    ├── 3.2. Ввести имя (обязательное поле)
    ├── 3.3. Ввести номер телефона (обязательное поле)
    ├── 3.4. При желании оставить комментарий к записи
    ├── 3.5. Нажать «Подтвердить запись»
    ├── 3.6. Увидеть окно «Запись подтверждена» с деталями записи
    └── 3.7. Нажать «Отлично!» → возврат на главную страницу
```

## 2. Функциональные требования

Формат: «Система должна [действие], когда [условие]».

### Экран 1. Выбор услуги

| № | Требование |
|---|---|
| FR-1 | Система должна отображать список категорий услуг, когда клиент открывает экран выбора услуги. |
| FR-2 | Система должна по умолчанию выделять первую категорию и показывать её услуги, когда экран открывается впервые. |
| FR-3 | Система должна отображать для каждой услуги название, описание, длительность в минутах и стоимость в рублях, когда клиент выбирает категорию. |
| FR-4 | Система должна сохранять выбранную услугу и переводить клиента на экран выбора даты и времени, когда клиент нажимает «Выбрать» у услуги. |

### Экран 2. Дата и время

| № | Требование |
|---|---|
| FR-5 | Система должна показывать календарь текущего месяца с выбранным по умолчанию сегодняшним днём, когда клиент открывает экран выбора даты. |
| FR-6 | Система должна запрещать выбор дней раньше текущей даты и отображать их неактивными. |
| FR-7 | Система должна показывать слоты времени выбранного дня, отмечать занятые слоты как недоступные и сбрасывать ранее выбранное время, когда клиент выбирает другой день. |
| FR-8 | Система должна показывать сообщение «Пожалуйста, выберите время» и не переходить дальше, когда клиент нажимает «Далее», не выбрав время. |

### Экран 3. Подтверждение

| № | Требование |
|---|---|
| FR-9 | Система должна отображать детали визита (услуга, дата и время, мастер, длительность, сумма к оплате), когда клиент открывает экран подтверждения. |
| FR-10 | Система должна не давать подтвердить запись, когда не заполнено имя или номер телефона. |
| FR-11 | Система должна показывать окно «Запись подтверждена» с деталями записи, когда клиент нажимает «Подтвердить запись» с корректно заполненной формой. |
| FR-12 | Система должна перенаправлять клиента на экран выбора услуги, когда он открывает экран подтверждения без выбранной услуги, даты или времени. |
