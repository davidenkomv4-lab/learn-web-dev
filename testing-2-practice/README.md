## Задание 2.2. Баг-репорт

| Поле | Значение |
|---|---|
| **ID** | BUG-001 |
| **Заголовок** | [Подтверждение записи] Поле «Номер телефона» принимает буквы и спецсимволы, маска +7 не применяется — запись подтверждается с некорректным номером |
| **Серьёзность (Severity)** | Major (значительная) |
| **Приоритет (Priority)** | High (высокий) |
| **Компонент** | Шаг 3 «Подтверждение записи», форма «Контактные данные», поле «Номер телефона» |
| **Окружение** | Windows 11 Pro 23H2; Google Chrome 130 (64-bit); разрешение 1920×1080; тестовый стенд ÉLAIRE (сборка от 12.11.2026) |
| **Автор / дата** | Тестировщик ÉLAIRE, 12.11.2026 |

**Предусловия**
1. Открыт сайт ÉLAIRE.
2. Выбрана услуга «Стрижка женская», дата — любой доступный день, время 12:00.
3. Открыт экран «Подтверждение записи».

**Шаги воспроизведения**
1. В поле «Ваше имя» ввести «Анна Петрова».
2. Кликнуть в поле «Номер телефона».
3. Ввести с клавиатуры `abc!@#$%привет`.
4. Нажать «Подтвердить запись».

**Ожидаемый результат**
- На шаге 2 в поле автоматически подставляется префикс `+7` и маска `+7 (___) ___-__-__`.
- На шаге 3 буквы и спецсимволы не вводятся — поле принимает только цифры.
- На шаге 4 запись с неполным или некорректным номером не подтверждается: поле подсвечивается, выводится подсказка «Введите номер телефона в формате +7 (999) 123-45-67».

**Фактический результат**
- Маска и префикс `+7` не появляются.
- В поле вводится `abc!@#$%привет` без ограничений.
- После нажатия «Подтвердить запись» открывается окно «Запись подтверждена» — запись создана с некорректным номером телефона.

**Частота воспроизведения:** 5 из 5 (стабильно).

**Дополнительные данные (вложения)**
- Скриншот 1: экран «Подтверждение записи» с введённым значением `abc!@#$%привет` в поле «Номер телефона» (поле выделено рамкой).
- Скриншот 2: открытое окно «Запись подтверждена» сразу после нажатия кнопки — видно, что запись прошла.
- Короткая видеозапись (GIF) шагов 2–4.
- DevTools → Console: ошибок нет (валидация на клиенте отсутствует, а не падает).
- DevTools → Network: запрос на создание записи (если есть) с телом, где `phone: "abc!@#$%привет"`.
- Значение `localStorage["elair-booking"]` на момент подтверждения.

**Обоснование серьёзности и приоритета**
Серьёзность **Major**: основной сценарий не падает, но салон получает запись, по которой невозможно связаться с клиентом (подтвердить визит, предупредить о переносе) — нарушена ключевая бизнес-функция. Приоритет **High**: дефект затрагивает каждую запись и напрямую ведёт к потере клиентов и неявкам, поэтому его нужно исправить в ближайшем релизе.

## Задание 2.3. Use Case

Сценарий разветвляется в самом начале: клиент может идти **от услуги** или **от мастера**.
Поэтому описан один основной Use Case (UC-01, через услугу), а вход через мастера —
отдельным Use Case (UC-02), который переиспользует общие шаги UC-01.

### UC-01. Клиент записывается на услугу (через выбор услуги)

| Поле | Значение |
|---|---|
| **Действующее лицо** | Клиент салона |
| **Цель** | Записаться на нужную услугу в удобное время |
| **Предусловия** | Клиент открыл сайт ÉLAIRE; у салона есть свободное время |
| **Постусловия (успех)** | Запись сохранена; клиент видит подтверждение с деталями визита |
| **Триггер** | Клиент нажимает «Записаться на услугу» на главной странице |

**Основной сценарий**
1. Клиент нажимает «Записаться на услугу».
2. Система показывает экран «Выбор услуги» со списком категорий; первая категория выбрана.
3. Клиент выбирает категорию.
4. Система показывает услуги категории: название, описание, длительность, цена.
5. Клиент нажимает «Выбрать» у услуги.
6. Система показывает экран «Дата и время» с календарём текущего месяца и слотами на выбранный день.
7. Клиент выбирает день.
8. Система показывает свободные и занятые слоты выбранного дня.
9. Клиент выбирает свободный слот и нажимает «Далее».
10. Система показывает экран «Подтверждение записи» с деталями визита и формой контактов.
11. Клиент вводит имя и номер телефона (и при желании комментарий) и нажимает «Подтвердить запись».
12. Система проверяет данные, сохраняет запись и показывает окно «Запись подтверждена».
13. Клиент нажимает «Отлично!»; система открывает главную страницу.

**Расширения (альтернативные и негативные ветки)**

| Шаг | Условие | Поведение системы |
|---|---|---|
| 1a | Клиент начинает с кнопки «Выбрать мастера» | Переход к UC-02 |
| 4a | В категории нет услуг | Показывается сообщение «В этой категории пока нет услуг»; клиент выбирает другую категорию (возврат к шагу 3) |
| 6a | Нужен другой месяц | Клиент листает месяцы стрелками «‹» / «›»; при переходе декабрь → январь меняется год |
| 7a | Клиент кликает по прошедшему дню | День неактивен, выбор не происходит |
| 8a | На выбранный день нет свободных слотов | Показывается сообщение «Свободного времени нет»; клиент выбирает другой день (возврат к шагу 7) |
| 8b | Клиент меняет день после выбора времени | Выбранное время сбрасывается, показываются слоты нового дня |
| 9a | Клиент нажимает «Далее», не выбрав время | Сообщение «Пожалуйста, выберите время», переход не выполняется |
| 9b | Клиент нажимает «←» (назад) | Возврат на экран «Выбор услуги» (шаг 2) |
| 11a | Не заполнено имя или телефон | Запись не подтверждается, пустое поле подсвечивается с подсказкой |
| 11b | Телефон введён в неверном формате | Запись не подтверждается, подсказка о формате +7 (999) 123-45-67 |
| 12a | Пока клиент заполнял форму, слот заняли | Сообщение «Это время уже занято», возврат к шагу 7 с актуальными слотами |
| 12b | Ошибка сервера / нет соединения | Сообщение об ошибке и кнопка «Повторить»; введённые данные не теряются |
| 10a | Клиент открыл экран подтверждения напрямую, без выбранной услуги или времени | Система перенаправляет на экран «Выбор услуги» |

### UC-02. Клиент записывается к выбранному мастеру

| Поле | Значение |
|---|---|
| **Действующее лицо** | Клиент салона |
| **Цель** | Записаться к конкретному мастеру |
| **Предусловия** | Клиент открыл сайт ÉLAIRE |
| **Триггер** | Клиент нажимает «Выбрать мастера» на главной странице или карточку мастера в блоке «Наши мастера» |

**Основной сценарий**
1. Клиент нажимает «Выбрать мастера».
2. Система показывает список мастеров: имя, специализация, рейтинг.
3. Клиент выбирает мастера.
4. Система показывает только услуги, которые оказывает этот мастер.
5. Клиент выбирает услугу.
6. Далее — шаги 6–13 из UC-01, но в слотах показывается только свободное время выбранного мастера.

**Расширения**

| Шаг | Условие | Поведение системы |
|---|---|---|
| 2a | Нет доступных мастеров | Сообщение «Нет доступных мастеров», предложение записаться через выбор услуги (UC-01) |
| 4a | У мастера нет услуг в нужной категории | Сообщение и предложение выбрать другого мастера (возврат к шагу 2) |
| 6a | У мастера нет свободных слотов в ближайшие дни | Сообщение «У мастера нет свободного времени» и предложение выбрать другого мастера или другой месяц |
